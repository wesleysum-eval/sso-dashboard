<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> /api/data/cdn-traffic | Untrusted input crosses here: only the verified `session` cookie is trusted for tenant resolution; any query string or header the client appends is never read for scoping. |
| Edge Function -> teo.tencentcloudapi.com | Outbound call carrying the real account's SecretId/SecretKey in the request signature; the response (including any `Response.Error`) is untrusted output that must not be forwarded verbatim to the browser. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Elevation of Privilege | edge-functions/api/data/cdn-traffic.js | critical | mitigate | `ZoneIds` is set exclusively from `getTenantAccount(payload.tenant_id)`, where `payload` comes only from `verifySession()` — no code path in this file reads a client-supplied scoping value (D-02/D-03, this phase's top risk per PROJECT.md). |
| T-03-02 | Information Disclosure | edge-functions/api/data/cdn-traffic.js response | high | mitigate | `account.secretId`/`account.secretKey` and `teoResponse.Response.Error` are never included in any response; every failure branch returns the same generic `{ available: false }` shape (D-05). |
| T-03-03 | Tampering | edge-functions/lib/teo-signer.js | medium | mitigate | A fresh `Date.now()`-based timestamp is computed per signed request; Tencent's signature expires after a 5-minute clock-skew window, bounding replay risk even if a signed request were intercepted in transit. |
| T-03-04 | Spoofing | edge-functions/api/data/cdn-traffic.js (unauthenticated access) | high | mitigate | `verifySession()` is called first, before any KV read or outbound call; a missing/invalid session returns 401 immediately (same pattern as Phase 2's AUTH-03 enforcement). |
