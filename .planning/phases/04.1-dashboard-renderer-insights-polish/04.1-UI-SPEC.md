**Hard constraints carried from `04-UI-SPEC.md`/`04.1-CONTEXT.md`:**

## Data Display Contract

> Extra section beyond the standard template, because this phase's core deliverable is a display-formatting contract, not new interactive surfaces. Resolves `04.1-CONTEXT.md` D-04's `METRIC_LABELS` lookup content directly from `04-RESEARCH.md`'s already-cited Tencent Cloud metric meanings — no new research needed.

### Metric Label & Unit Contract

The `METRIC_LABELS` lookup (`generation-schema.js`) must map every value in `METRICS_BY_SOURCE` to exactly this `{ label, unit, format }` shape. `format` selects the Numeric Formatting Rule below.

**`cdn-traffic`:**

| Metric code | Label | Unit | Format rule |
|-------------|-------|------|-------------|
| `l7Flow_outFlux` | Outbound Traffic | Bytes | `bytes-binary` |
| `l7Flow_inFlux` | Inbound Traffic | Bytes | `bytes-binary` |
| `l7Flow_flux` | Total Traffic | Bytes | `bytes-binary` |
| `l7Flow_outBandwidth` | Outbound Bandwidth | bps | `bandwidth-decimal` |
| `l7Flow_inBandwidth` | Inbound Bandwidth | bps | `bandwidth-decimal` |
| `l7Flow_bandwidth` | Total Bandwidth | bps | `bandwidth-decimal` |
| `l7Flow_request` | Request Count | requests | `integer-grouped` |
| `l7Flow_avgResponseTime` | Avg Response Time | ms | `ms-rounded` |
| `l7Flow_avgFirstByteResponseTime` | Avg First-Byte Time | ms | `ms-rounded` |
| `l7Flow_requestRate` | Request Rate | req/s | `rate-1dp` |

**`security-events`:**

| Metric code | Label | Unit | Format rule |
|-------------|-------|------|-------------|
| `ddos_attackMaxBandwidth` | Peak Attack Bandwidth | bps | `bandwidth-decimal` |
| `ddos_attackMaxPackageRate` | Peak Attack Packet Rate | pps | `integer-grouped` |
| `ddos_attackBandwidth` | Attack Bandwidth | bps | `bandwidth-decimal` |
| `ddos_attackPackageRate` | Attack Packet Rate | pps | `integer-grouped` |

**[auto] `D-UI-09`: Fallback if a future metric is added to the closed enum without a matching `METRIC_LABELS` entry** — render the raw metric code as the label (today's existing behavior) rather than throwing or showing a blank title. This is the same graceful-degradation discipline as every other fail-open-to-generic-default rule in this codebase (D-08 lineage) — never a hard failure over a missing display label.

### Numeric Formatting Rules

| Rule | Behavior |
|------|----------|
| `bytes-binary` | `<1024` → `"{n} B"`; `<1024²` → `"{n/1024 to 1dp} KB"`; `<1024³` → `"{n/1024² to 1dp} MB"`; else `"{n/1024³ to 1dp} GB"`. **[auto] `D-UI-10`:** binary (1024) scaling chosen — matches the colloquial "GB" most CDN/traffic dashboards use, including Tencent's own console. |
| `bandwidth-decimal` | `<1000` → `"{n} bps"`; `<1e6` → `"{n/1000 to 1dp} Kbps"`; `<1e9` → `"{n/1e6 to 1dp} Mbps"`; else `"{n/1e9 to 1dp} Gbps"`. **[auto] `D-UI-11`:** decimal (1000) scaling for bandwidth specifically — standard networking convention (e.g. "100 Mbps" is decimal, not binary), intentionally different base from `bytes-binary` above. |
| `integer-grouped` | Integer, thousands-separated (e.g. `"12,483 requests"`, `"340 pps"`) — no decimals. |
| `ms-rounded` | Rounded to nearest integer, `" ms"` suffix (e.g. `"142 ms"`). |
| `rate-1dp` | One decimal place, `" req/s"` suffix (e.g. `"18.4 req/s"`). |

Zero values render as `"0 {unit}"` (e.g. `"0 requests"`), never blank/dash — matches the existing no-blank-state discipline.

### Timestamp Format Contract

Replaces the raw `point.Time`/`point.Timestamp` pass-through `04.1-CONTEXT.md` D-01 flags as a root cause.

| `interval` value | Display format | Example |
|------------------|-----------------|---------|
| `hour` | Month-abbrev, day, time (no year — always current-ish range) | `"Aug 13, 3:00 PM"` |
| `day` | Month-abbrev, day only | `"Aug 13"` |

Applies uniformly across: chart x-axis labels/tooltips, table "Time" column, and the spike-callout's `{formatted timestamp}` substitution — one formatting function, three call sites, never three divergent formats for the same underlying point.

## Insight Computation Contract

> Extra section — the exact deterministic formulas for D-04's computed (never LLM-invented) insight elements, so planning doesn't have to re-derive them. All three computations run **client-side in `app.js`**, over the same already-fetched, already-validated `widget.data` series `extractSeries()` already produces — no new server call, no new LLM call.

### Hero-metric selection — `[auto] D-UI-12`

- The **first `stat-card` widget** encountered in the validated widget array (in the LLM's returned order — no reordering) is the hero metric. If no `stat-card` widget exists in the dashboard, no hero treatment is applied anywhere (never promotes a chart/table widget instead).
- At most one hero per dashboard.
- Visual treatment: `.widget-card.is-hero` gets a 4px solid `var(--color-primary)` left border (replacing its normal full border on that one edge) and its `.stat-card-value` text color switches to `var(--color-primary)` — same 28px/600 size, per the Typography section above. No badge/label text is added ("HERO" text is explicitly NOT shown — the border+color treatment alone is the signal, keeping this a pure CSS emphasis rather than a new copy element).

### Spike-callout — `[auto] D-UI-13`

- Applies **only** to `line-chart` and `bar-chart` widgets (not `stat-card`/`table`) — matches the phase's own framing ("layered on existing charts").
- Threshold: `2 × arithmetic mean` of all points in that widget's series.
- If the series' **single highest point** exceeds the threshold, render one `.spike-callout` below that widget's chart canvas using the Copywriting Contract's spike template above, with `{multiplier}` = `(point value / mean)` rounded to 1 decimal place.
- If no point exceeds the threshold, render **nothing** — no "no spike detected" text, no placeholder (this is a silent, computed absence, not a UI state requiring copy).
- At most one spike-callout per widget (only the single highest point is ever flagged, never a list of multiple points — intentionally lighter-weight than the Phase 999.1 Template 3 backlog idea, see Relationship to Backlog note below).

### Summary-insight sentence — `[auto] D-UI-14`

- Applies to `line-chart` and `bar-chart` widgets only (same scope as the spike-callout — `stat-card`/`table` widgets do not get a summary sentence, since a stat-card is already a single computed number and a table already shows every point).
- Computed stats: `min`, `max`, `avg` (arithmetic mean) of the series, each formatted per that widget's `Numeric Formatting Rule` (same lookup as the widget's own value display — never a differently-formatted number within the same widget).
- Trend: compare the average of the first half of the series to the average of the second half. If the second-half average is `>5%` higher → `"up"`; `>5%` lower → `"down"`; otherwise → `"flat"`.
- Rendered as one `.insight-summary` line below the chart (and below the spike-callout, if present) using the Label role (13px/400, `--color-text-muted`) — plain prose, no accent color, per the Color section above.

### `dashboardTitle` display — `[auto] D-UI-15`

- If `dashboardTitle` is present and passes the same free-text/length-cap validation pattern `04.1-CONTEXT.md` D-05 describes (mirroring `widget.title`'s existing validation), it replaces the static "Generate a dashboard" `<h2>` text in `.prompt-panel` (same 20px/600 Heading role, same element, just different `textContent`).
- If absent or invalid, the `<h2>` falls back to the existing default text **"Your Dashboard"** (see Copywriting Contract) rather than the current literal "Generate a dashboard" label — this fallback only takes effect once at least one dashboard has been generated; before the first generation, the pre-existing "Generate a dashboard" prompt-panel heading is unchanged (this phase does not touch the pre-generation empty-state heading).

### Relationship to backlog Template 3 (`04.1-CONTEXT.md` D-07)

This phase's spike-callout (single-point, `2× mean` threshold, one callout max per widget) is a deliberately **lighter-weight** implementation than `ROADMAP.md` Backlog Phase 999.1 Template 3's proposed `derivedLogic` field (`max_point_vs_rolling_average` / `highlight_points_over_2x_average` / `list_points_over_threshold`, which supports multi-point highlighting and a true rolling average). This document does **not** adopt Template 3's `derivedLogic` field name or schema — if Template 3 is ever promoted from the backlog, its design should explicitly decide whether to extend or replace this phase's simpler client-side computation, not silently duplicate it.
