**Fail-closed validation pattern to extend for `dashboardTitle`** (lines 39-68):
```javascript
export function validateWidget(widget, dataSource) {
  if (!widget || typeof widget !== 'object') return null;

  const { componentType, metric, interval, timeRange, title } = widget;

  if (!COMPONENT_TYPES.includes(componentType)) return null;
  if (!METRICS_BY_SOURCE[dataSource] || !METRICS_BY_SOURCE[dataSource].includes(metric)) {
    return null;
  }
  if (!INTERVALS.includes(interval)) return null;
  if (!TIME_RANGES.includes(timeRange)) return null;

  return {
    componentType,
    metric,
    interval,
    timeRange,
    title: String(title || '').slice(0, 120),
  };
}
```
`title`'s exact treatment (`String(title || '').slice(0, 120)` — free-text, capped, never validated against an enum, never used for anything but display) is the literal precedent `04.1-CONTEXT.md` D-05 says `dashboardTitle` must mirror. `dashboardTitle` validation should be a small parallel function (e.g. `validateDashboardTitle(raw)`) returning either the capped string or `null`/default — same fail-soft-to-default shape as this file's header comment describes ("never coerce... never throw"), but note `04.1-UI-SPEC.md`'s Copywriting Contract wants a *fallback default* ("Your Dashboard") rather than `null` propagating to a blank heading, so the null-handling happens at the render call site (`app.js`), not by inventing a second return convention here.

### `edge-functions/api/generate.js` (controller/route, request-response)

**Analog:** itself

**`buildSystemPrompt()` schema-description pattern** (lines 62-87):
```javascript
function buildSystemPrompt(dataSource, previousSpec) {
  const metrics = METRICS_BY_SOURCE[dataSource] || [];

  const lines = [
    'You generate dashboard widget specifications as JSON only.',
    'You must return ONLY a JSON array of widget objects — no markdown code fences, no explanation text, nothing before or after the array.',
    'Each widget object must have exactly these fields: componentType, metric, interval, timeRange, title.',
    `componentType must be one of: ${COMPONENT_TYPES.join(', ')}.`,
    `metric must be one of: ${metrics.join(', ')}.`,
    `interval must be one of: ${INTERVALS.join(', ')}.`,
    `timeRange must be one of: ${TIME_RANGES.join(', ')}.`,
    'title is a short, free-text, human-readable label for the widget (not used for anything else).',
    'Never use any value outside these exact lists — any other value will be silently rejected.',
    'Return between 1 and 4 widgets that best answer the user prompt.',
  ];

  if (previousSpec) {
    lines.push(
      'The user is refining a previous dashboard. Here is the previous widget specification as context (JSON):',
      JSON.stringify(previousSpec),
      'Adjust it according to the new prompt below rather than starting from nothing, unless the new prompt clearly asks for something unrelated.',
    );
  }

  return lines.join('\n');
}
```
`dashboardTitle` (D-05) needs one more line in this same array, worded like the existing `title` line (free-text, display-only, not used for anything else) — e.g. `'Additionally include a top-level "dashboardTitle" field (sibling of the widget array, not per-widget) — a short, free-text, human-readable title for the whole dashboard (not used for anything else).'`. Note the schema shape question this raises: today the LLM returns a bare JSON *array* of widgets (line 66 says "ONLY a JSON array"); adding a sibling `dashboardTitle` means either (a) changing the top-level shape to `{ dashboardTitle, widgets: [...] }` and updating `callAiGateway()`'s consumer accordingly, or (b) keeping the array shape and dropping `dashboardTitle` as a duplicated field on every widget object, then reading it off `validWidgets[0]` — planning must pick one; option (a) is cleaner but touches `candidates` parsing below.

```javascript
const widgets = [];
for (const widget of validWidgets) {
```

If `dashboardTitle` is added to the response, it's assembled once (outside the per-widget loop, since it's dashboard-level, not per-widget) and merged into the final `Response(JSON.stringify({ ... }))` call alongside the existing `widgets`/`prompt` fields — same flat-object response shape, no new response wrapper type.

**Generic-failure convention (D-08) to preserve** (lines 54-60):
```javascript
function generationFailed() {
  return new Response(JSON.stringify({ error: 'generation_failed' }), {
```

### `app.js` (component/utility, transform + event-driven)

**Analog:** itself

**`extractSeries()` — where timestamp formatting must be added** (lines 323-360):
```javascript
function extractSeries(data) {
  if (!Array.isArray(data) || data.length === 0) return null;

  const first = data[0];
  const typeValues = [
    ...(Array.isArray(first?.TypeValue) ? first.TypeValue : []),
    ...(Array.isArray(first?.FloatTypeValue) ? first.FloatTypeValue : []),
  ];
  const detail = typeValues[0]?.Detail;

  if (Array.isArray(detail) && detail.length > 0) {
    const series = detail
      .map((point) => {
        const label =
          point.Timestamp !== undefined
            ? new Date(point.Timestamp * 1000).toLocaleString()
            : point.Time ?? point.time ?? '';
        const value = Number(point.Value ?? point.value);
        return { label: String(label), value };
      })
      .filter((point) => !Number.isNaN(point.value));
    return series.length > 0 ? series : null;
  }

  // Flat array of { Time/time, Value/value } points directly.
  if (first && (first.Time !== undefined || first.time !== undefined)) {
    const series = data
      .map((point) => {
        const label = point.Time ?? point.time ?? '';
        const value = Number(point.Value ?? point.value);
        return { label: String(label), value };
      })
      .filter((point) => !Number.isNaN(point.value));
    return series.length > 0 ? series : null;
  }

  return null;
}
```
Both `label` assignments (`new Date(point.Timestamp * 1000).toLocaleString()` and the raw `point.Time ?? point.time ?? ''` passthrough) are exactly the D-01 root-cause bug `04.1-CONTEXT.md` flags: `toLocaleString()` produces a locale/browser-dependent full timestamp, not the UI-SPEC's `"Aug 13, 3:00 PM"` (hour) / `"Aug 13"` (day) format, and the raw-passthrough branch shows the unformatted API string verbatim. Per the Timestamp Format Contract, a single new formatting function (e.g. `formatTimestamp(rawValue, interval)`) should replace both inline expressions — called once from `extractSeries()` so chart/table/spike-callout all share one formatter (never three divergent formats, per the UI-SPEC's explicit "one formatting function, three call sites" instruction). Note `extractSeries()` does not currently receive `interval` as a parameter — its signature will need to grow (`extractSeries(data, interval)`) or callers must format after-the-fact; this parameter-threading decision is left to planning.

**`widgetCardShell()` — the exact D-01 title-fallback bug** (lines 362-373):
```javascript
function widgetCardShell(widget) {
  const card = document.createElement('div');
  card.className = 'widget-card';

  const title = document.createElement('div');
  title.className = 'widget-card-title';
  title.textContent = widget.title || widget.metric;
  title.title = widget.title || widget.metric;
  card.appendChild(title);

  return card;
}
```
Both `widget.title || widget.metric` fallback sites are the literal bug — `widget.metric` is the raw `teo` code (e.g. `l7Flow_outFlux`). The fix (per Copywriting Contract's "Widget title fallback" row) replaces `widget.metric` with a `METRIC_LABELS[widget.metric]?.label ?? widget.metric` lookup (D-UI-09's graceful-degradation fallback: raw code only if the lookup itself misses). This function is also the natural place to add `.widget-card.is-hero`'s class (D-UI-12) — the hero-detection logic (first `stat-card` in the array) must be computed by the caller (`renderWidgets()`) and passed in, since `widgetCardShell()` itself has no knowledge of the widget's position in the array.

**`renderStatCardWidget()` — unit-less raw-number display, needs the same fix** (lines 418-431):
```javascript
function renderStatCardWidget(widget) {
  const series = extractSeries(widget.data);
  if (!series) return renderPlaceholder(widget);

  const total = series.reduce((sum, point) => sum + point.value, 0);

  const card = widgetCardShell(widget);
  const value = document.createElement('div');
  value.className = 'stat-card-value';
  value.textContent = String(Math.round(total * 100) / 100);
  card.appendChild(value);

  return card;
}
```
`String(Math.round(total * 100) / 100)` is a bare rounded number with no unit — needs to route through the new Numeric Formatting Rules (`bytes-binary`/`bandwidth-decimal`/`integer-grouped`/`ms-rounded`/`rate-1dp`) keyed by `METRIC_LABELS[widget.metric]?.format`. This is also the hero-metric value element (`.stat-card-value`) the UI-SPEC's `D-UI-12` targets for the accent-color override when `.widget-card.is-hero` is applied.

**`renderChartWidget()` — insertion point for spike-callout + summary-insight** (lines 386-416):
```javascript
function renderChartWidget(widget, chartType) {
  const series = extractSeries(widget.data);
  if (!series) return renderPlaceholder(widget);

  const card = widgetCardShell(widget);

  const canvas = document.createElement('canvas');
  card.appendChild(canvas);

  if (typeof Chart === 'undefined') return renderPlaceholder(widget);

  new Chart(canvas.getContext('2d'), {
    type: chartType,
    data: {
      labels: series.map((point) => point.label),
      datasets: [
        {
          label: widget.title || widget.metric,
          data: series.map((point) => point.value),
          backgroundColor: '#0052d9',
          borderColor: '#0052d9',
        },
      ],
    },
    options: {
      plugins: { legend: { display: false } },
    },
  });

  return card;
}
```
Per D-UI-13/D-UI-14, after `card.appendChild(canvas)` and the `new Chart(...)` call, two new elements get conditionally appended to `card`: a `.spike-callout` (only if the series' max point exceeds `2 × mean`) and an `.insight-summary` (always, for chart widgets) — both computed from the same `series` array already in scope here, no new fetch. `widget.title || widget.metric` on the dataset `label:` line has the identical D-01 bug as `widgetCardShell()` and needs the same `METRIC_LABELS` lookup fix. The `backgroundColor`/`borderColor: '#0052d9'` hardcoded hex should be read from `getComputedStyle` or simply left as-is (it's already the `--color-primary` value duplicated as a literal, pre-existing minor inconsistency, not a hero-treatment site — the UI-SPEC's `D-UI-12` hero accent applies to `.stat-card-value` and the border, not the chart's own dataset color).

**`saveDashboard()` — where "Copy Link" and the state badge attach** (lines 593-636):
```javascript
function saveDashboard(bar, btn) {
  btn.disabled = true;
  btn.textContent = 'Saving…';

  fetch('/api/dashboard', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ spec: draft.spec, data: draft.data, prompt: draft.prompt }),
  })
    .then((r) => r.json().then((body) => ({ ok: r.ok, body })))
    .then(({ ok, body }) => {
      if (ok && body && body.dashboardId) {
        bar.textContent = '';
        const confirmation = document.createElement('div');
        confirmation.className = 'save-confirmation';
        const label = document.createElement('span');
        label.textContent = 'Saved \u2713 — Dashboard saved. Bookmark this link to view it again: ';
        confirmation.appendChild(label);
        const link = document.createElement('a');
        const url = new URL(window.location.href);
        url.search = '';
        url.searchParams.set('dashboard', body.dashboardId);
        link.href = url.toString();
        link.textContent = url.toString();
        confirmation.appendChild(link);
        bar.appendChild(confirmation);
      } else { /* ... showSaveError ... */ }
    })
    .catch(() => { /* ... showSaveError ... */ });
}
```
Per D-UI-16, the "✓ Saved" badge update happens in this exact success branch (`if (ok && body && body.dashboardId)`), driven off the same already-in-memory response — never a new fetch. The `.copy-link-btn` (D-UI-13/Component notes) is appended to `confirmation` right after the `link` element, using `navigator.clipboard.writeText(url.toString())` with a `.then()`/`.catch()` toggling the button's `textContent` between "Copy Link" and "Copied!" (2s revert via `setTimeout`) — silent no-op on failure per the Copywriting Contract (no new `.catch()` error path needed beyond leaving the label unchanged).

**`renderRetrievalView()` — where the "Saved · Read-only" badge variant attaches (D-UI-17)** (lines 651-699, already read in full above): the success branch at `if (ok && body && Array.isArray(body.spec))` (calls `renderWidgets(body.spec)`) is where the badge is unconditionally set to "✓ Saved · Read-only" — same trigger point, no separate state machine.

### Fail-soft-to-default (never a distinct error state)
**Source:** `edge-functions/api/generate.js` lines 54-60 (`generationFailed()`) and `04.1-UI-SPEC.md`'s D-UI-09/Copywriting Contract
**Apply to:** `METRIC_LABELS` lookup misses (fall back to raw code), `dashboardTitle` validation failures (fall back to "Your Dashboard"), Copy Link clipboard failures (silent no-op)
Every new failure branch this phase introduces degrades to a default/fallback value or silent no-op — never a new distinct error banner/state, matching the D-08 lineage already established project-wide.

### textContent/createElement only, never innerHTML
**Source:** `app.js` lines 308-310 (file header comment) and consistently every render function in the file (e.g. lines 366-369, 612-621)
**Apply to:** all new render code — `dashboardTitle`, summary-insight sentence, spike-callout sentence, dashboard-state badge text
```javascript
title.textContent = widget.title || widget.metric;
```
No new render site in this phase may use `innerHTML`, even though the spike-callout/summary-insight strings are computed client-side (not raw LLM output) — `04.1-UI-SPEC.md` explicitly calls out that this discipline applies "as a matter of consistent practice, not because they are untrusted."

### Per-item failure tolerance (one bad item never breaks siblings)
**Source:** `app.js`'s `extractSeries()` returning `null` per malformed widget (renders `.widget-placeholder` instead, lines 375-384) and `generate.js`'s per-widget `continue` on `teo` fetch failure (lines 222-232)
**Apply to:** hero-metric selection (if no `stat-card` exists, skip hero treatment entirely — don't break other widgets), spike-callout (no qualifying point = render nothing, not an error)
