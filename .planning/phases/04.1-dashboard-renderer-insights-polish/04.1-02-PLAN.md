## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app.js -> navigator.clipboard | Native browser Web API, same-origin, user-gesture-triggered (click) — standard browser permission model applies, no server involvement. |
| app.js badge state -> DOM | Purely presentational; badge text is always one of four server-controlled-by-app-logic literal strings, never interpolated from LLM/user input. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04.1-05 | Information Disclosure | navigator.clipboard.writeText (Copy Link) | low | accept | Writes only the already-rendered, already-visible bookmarkable dashboard URL (same tenant-scoped, session-gated resource the user already has access to) — no new data is exposed beyond what the adjacent link already displays in plaintext. |
| T-04.1-06 | Denial of Service (minor) | Clipboard permission denial | low | accept | A rejected clipboard promise is caught and silently ignored (button stays "Copy Link") — no exception propagates, no error banner, no broken page state (Task 2). |
| T-04.1-07 | Tampering | Dashboard-state badge text | low | accept | Badge text is always one of exactly four hardcoded literal strings set by app.js's own control flow — never interpolated from server response bodies, LLM output, or user input, so there is no injection surface even though the badge sits in the DOM. |

</threat_model>
