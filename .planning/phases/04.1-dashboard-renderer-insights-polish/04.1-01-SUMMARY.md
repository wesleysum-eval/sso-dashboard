# Phase 4.1 Plan 1: Dashboard Renderer & Insights Polish Summary

**Root-cause fix for raw-metric-code widget titles/unitless values/unformatted timestamps, plus computed-only hero-metric, spike-callout, and summary-insight framing layered on Phase 4's already-fetched dashboard data — GEN-03's closed generation vocabulary untouched.**

## Accomplishments

- Added `METRIC_LABELS` (14 metric codes → `{label, unit, format}`) to `generation-schema.js`, mirrored verbatim client-side in `app.js` (no module system to import from `edge-functions/`); `widgetCardShell()`, `renderChartWidget()`'s dataset label, `renderStatCardWidget()`, and `renderTableWidget()` all now use it instead of the raw `teo` metric code / bare unformatted numbers.
- Added `formatMetricValue()` (5 numeric formatting rules: `bytes-binary`, `bandwidth-decimal`, `integer-grouped`, `ms-rounded`, `rate-1dp`) and `formatTimestamp()` (hour/day format per `04.1-UI-SPEC.md`'s Timestamp Format Contract) as pure functions in `app.js`; `extractSeries()` now accepts an `interval` parameter and routes both of its label-assignment branches through `formatTimestamp()`.
- Added `computeStats()`/`computeTrend()`/`detectSpike()` pure functions computing min/max/avg, up/down/flat trend, and a single-point 2x-mean spike — all operating only on already-fetched, already-validated `widget.data`, with zero new fetch and zero new LLM call. `renderWidgets()` threads an `isHero` flag through `renderWidget()` to `renderStatCardWidget()` so at most one stat-card (the first in LLM order) gets `.is-hero` styling; `renderChartWidget()` appends a `.spike-callout` (only when a genuine spike exists) and an `.insight-summary` sentence below every line/bar chart.
- Added `.widget-card.is-hero`, `.spike-callout`, `.insight-summary` CSS rules to `index.html`, built exclusively from existing `:root` tokens (zero new hex values).
- Added `validateDashboardTitle()` to `generation-schema.js` (mirrors `validateWidget()`'s free-text/capped/never-throw discipline, returns `null` on invalid input); changed `generate.js`'s LLM response contract from a bare JSON array to `{ dashboardTitle, widgets }`, validated `dashboardTitle` once at the dashboard level, and updated the retry-correction string to describe the new object shape. `app.js`'s generate success branch now updates `.prompt-panel h2` (given a stable `id="prompt-panel-heading"` in `index.html`) to the validated title or the `"Your Dashboard"` fallback, leaving the pre-generation heading untouched.

## Decisions Made

- `dashboardTitle` validated once at the dashboard level (not per-widget), returning `null` rather than an empty string on invalid input — the caller (client) owns the fallback text decision, matching `04.1-CONTEXT.md` D-05's design.
- LLM top-level response shape changed from a bare array to `{ dashboardTitle, widgets }` — an internal contract between `generate.js` and `app.js` only; no migration risk since no other consumer reads this shape (per the plan's own `<reversibility>` note on Task 3).
- Hero-metric selection strictly requires an existing `stat-card` widget in the array — no fallback promotion of a chart/table widget when none exists, per `04.1-UI-SPEC.md` D-UI-12.
- Spike-callout and summary-insight interpolate every number through the widget's own `METRIC_LABELS` format/unit, guaranteeing one consistent formatting convention per widget rather than a second divergent one for computed insight text.
