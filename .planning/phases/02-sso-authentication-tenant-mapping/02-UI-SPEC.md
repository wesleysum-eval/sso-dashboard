# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** Phase 2 is primarily backend (OIDC redirect flow, JWT session, server-side tenant mapping — see `02-RESEARCH.md`). It has exactly **two** real UI surfaces: the post-login home page and the generic access-denied page. There is no login-page UI (unauthenticated visits get an automatic server-side 302, decided below) and no data-source picker or prompt/dashboard UI — those belong to Phase 3 and Phase 4 respectively and are out of scope here. Tokens below (font, spacing, color) are chosen to carry forward cleanly into Phase 3/4's richer UI per user request, but this document only contracts Phase 2's two pages.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **"Select Data Source"** — rendered as a visually disabled/"coming soon" link on the post-login page (user decision: placeholder next-step link, since Phase 3's picker doesn't exist yet). Not clickable; styled with reduced opacity and a `title="Coming in Phase 3"` hint. |
| Post-login welcome heading | **"Welcome"** |
| Post-login welcome body | **"You're signed in as tenant `{tenant_id}`."** — tenant ID interpolated from the verified JWT session claim (user decision: welcome + tenant ID, useful for manually verifying AUTH-03 during this phase) |
| Empty state | Not applicable this phase — no list/collection UI exists in Phase 2 (both pages are single static content blocks, no data to be empty). |
| Error state (access-denied heading) | **"Access Denied"** |
| Error state (access-denied body) | **"Your account could not be verified. Contact your IT administrator."** (user decision — D-05 compliant: no tenant-mapping detail, no configured-domain hint, no reason code) |
| Destructive confirmation | Not applicable — Phase 2 has no destructive actions (no logout, no delete; AUTH-04 explicit logout is deferred to v2 per REQUIREMENTS.md). |

**Hard constraint carried from CONTEXT.md D-05:** The access-denied page must never vary its copy based on *why* mapping failed (missing claim vs. unrecognized tenant vs. malformed claim) — always the exact same two lines above, reached via the same redirect regardless of cause (see `02-RESEARCH.md` Pitfall 5).

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5) and lifted by plan-phase's
> `## UI Considerations` lift rule via the identical rule as SPEC `## Edge Coverage`. Shape-rooted UI *state*
> coverage (empty / loading / error / populated / partial / overflow / zero-one-many / long-text).
> Empty-state and error-state COPY live in `## Copywriting Contract` above — this section covers
> state coverage and REFERENCES those rows rather than restating the copy (de-dup).

Applicable state considerations resolved: 4 covered, 1 backstop, 0 unresolved, 3 dismissed (not applicable) — none applicable for `empty`/`zero-one-many` (no list-collection elements exist in Phase 2's UI).

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| loading | nav (login trigger) | ✅ covered | The login trigger is a synchronous server-side 302 issued by an Edge Function before any HTML renders (user decision: automatic redirect, no button) — there is no client-rendered loading state to design; the browser's native navigation handles the transition. |
| error | nav (OIDC callback) | ✅ covered | OIDC callback failures (invalid state/code, missing/unrecognized tenant claim) redirect to the static access-denied page — exact copy is the "Error state" rows in Copywriting Contract above (D-05 no-leak requirement). |
| populated | static-content (post-login page) | ✅ covered | Post-login home renders the "Welcome" heading + resolved tenant ID + placeholder "Select Data Source" link — exact copy in Copywriting Contract above. |
| long-text | static-content (tenant ID value) | 🧪 backstop | Tenant ID value must not overflow the 480px centered card. Resolution: truncate with CSS `text-overflow: ellipsis` at the container width, with a `title` attribute carrying the full value for hover. Needs a held-out visual check rendering a long (36+ char) test `tenant_id` to confirm no layout break. |
| partial | static-content (post-login page) | ✅ covered | Session JWT payload is minimal by design (`tenant_id`, `sub`, `iat`, `exp` only — per `02-RESEARCH.md` Pitfall 2) — there is no optional/partially-missing field on this page. Either the full welcome content renders (valid session + tenant claim) or the user is redirected to access-denied; no in-between partial-data state exists. |
| overflow | nav (placeholder CTA) | ✅ covered | "Select Data Source" is a single short, fixed, hardcoded label (not user- or IdP-supplied content) — no overflow risk; no truncation logic needed. |
| empty | — | ⚠ dismissed (not applicable) | No list-collection elements exist anywhere in Phase 2's UI — both pages (post-login, access-denied) are single static content blocks, never rendering zero-items data. |
| zero-one-many | — | ⚠ dismissed (not applicable) | Same reason as `empty` — no list-collection element exists in Phase 2's UI. |
