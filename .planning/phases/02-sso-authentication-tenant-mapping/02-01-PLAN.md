    Create package.json declaring dependencies `openid-client` (^6.8.5) and `jose` (^6.2.8); run `npm install`. Do not add a `cookie` or `js-cookie` package — EdgeOne's Edge Functions runtime injects a global `Cookies` API natively.
    Create edge-functions/lib/oidc-config.js exporting `async function getOidcConfig(env)`: imports `* as client from 'openid-client'`, calls `client.discovery(new URL(env.OIDC_ISSUER_URL), env.OIDC_CLIENT_ID, env.OIDC_CLIENT_SECRET)`, memoizes the result in a module-scope variable (best-effort warm-instance cache; not durable across cold starts, which is expected per RESEARCH.md Open Question 2). This is the generic/standards-compliant OIDC client per D-02: all three values come from per-customer env vars with zero vendor-specific branching (no Auth0-only or Okta-only code path) — the same `getOidcConfig` works for any IdP that exposes a standard discovery document.
    Create edge-functions/lib/session.js exporting `async function signSession({ tenantId, sub }, env)` — builds a JWT via jose's `SignJWT({ tenant_id: tenantId, sub })`, sets protected header `{ alg: 'HS256' }`, `.setIssuedAt()`, `.setExpirationTime('12h')` (12h default per RESEARCH.md Pitfall 4 — a fixed session length, not an access-token-style short expiry; reasonable default since D-06 has no revocation mechanism), signs with `new TextEncoder().encode(env.SESSION_SIGNING_KEY)`. Also export `async function verifySession(jwtString, env)` wrapping jose's `jwtVerify`, returning the payload on success and `null` on any thrown error (expired, tampered, malformed).
    Create edge-functions/api/auth/login.js: `onRequestGet(context)` calls `getOidcConfig(env)`, generates `code_verifier` via `client.randomPKCECodeVerifier()`, `code_challenge` via `client.calculatePKCECodeChallenge(code_verifier)`, `state` via `client.randomState()`, and `nonce` via `client.randomNonce()` (defense-in-depth alongside PKCE, per RESEARCH.md Alternatives Considered — "implement both" since the marginal cost is near zero). Builds the authorization URL via `client.buildAuthorizationUrl(config, { redirect_uri: env.OIDC_REDIRECT_URI, scope: 'openid profile email', code_challenge, code_challenge_method: 'S256', state, nonce })`. Stores `{ code_verifier, state, nonce }` JSON-stringified in a cookie named `oidc_txn` via EdgeOne's global `Cookies` API (`new Cookies()`, `.set('oidc_txn', ..., { httponly: true, secure: true, samesite: 'Lax', max_age: '600', path: '/' })`, then `response.setCookies(cookies)`). Returns a 302 `Response` with `Location` set to the built authorization URL. Use 302 (never 307) for this and every redirect in the flow, per RESEARCH.md Anti-Patterns.
    Create edge-functions/api/auth/callback.js: `onRequestGet(context)` reads the `oidc_txn` cookie via `new Cookies(request.headers.get('Cookie'))`; if absent, redirect 302 to `/access-denied.html`. Otherwise parse `{ code_verifier, state, nonce }` from it. Inside a try/catch, call `client.authorizationCodeGrant(config, new URL(request.url), { pkceCodeVerifier: code_verifier, expectedState: state, expectedNonce: nonce })` — on any throw (invalid/expired code, state mismatch, nonce mismatch), redirect 302 to `/access-denied.html`. On success, extract claims via `tokens.claims()` (already signature/issuer/audience-verified internally by openid-client — this is the ONLY place the claim is read from; never from `request.url`, query params, headers, or body). Call `signSession({ tenantId: claims.tenant_id, sub: claims.sub }, env)` and set a `session` cookie (`httponly: true, secure: true, samesite: 'Lax', max_age: '43200', path: '/'` — matching the JWT's 12h expiry), remove the `oidc_txn` cookie, and redirect 302 to `/`.
    Deploy via `git push origin main` and confirm the redeploy completes on the GitHub-connected project.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> Edge Function (login/callback) | Untrusted input crosses here: query params (`code`, `state`, any injected extras), cookies, headers. |
| Edge Function -> Customer IdP | Trusted only AFTER signature/issuer/audience verification inside `openid-client`'s `authorizationCodeGrant`; the raw HTTP response from the IdP is otherwise untrusted transport. |
| Edge Function -> EdgeOne env/secrets | `OIDC_CLIENT_SECRET` and `SESSION_SIGNING_KEY` read via `context.env`, following the established `status.js` pattern of never echoing raw secret values in any response. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering | edge-functions/api/auth/callback.js (state/PKCE validation) | critical | mitigate | `state` and `pkceCodeVerifier` checked via `expectedState`/`pkceCodeVerifier` inside `authorizationCodeGrant`; any mismatch throws and routes to access-denied (RFC 9700 §4.7.1). |
| T-02-02 | Spoofing | edge-functions/api/auth/callback.js (tenant claim extraction) | critical | mitigate | Tenant identity read exclusively from `tokens.claims()` after openid-client's internal ID-token signature/issuer/audience verification — never from client-supplied query params, headers, or body (Task 2, AUTH-03 hard requirement). |
| T-02-03 | Information Disclosure | access-denied.html + callback.js error branches | high | mitigate | Single generic static page; identical redirect (no `?reason=` param, no status/timing variance) for every failure mode — missing claim, invalid code, state mismatch (D-05, Task 2). |
| T-02-04 | Tampering | SESSION_SIGNING_KEY / OIDC_CLIENT_SECRET | critical | mitigate | Read only via `context.env` inside Edge Functions, following `status.js`'s established never-echo pattern; never logged or returned in any response body. |
| T-02-05 | Elevation of Privilege | callback.js claim-to-session issuance path | high | mitigate | Missing/unrecognized `tenant_id` always routes to access-denied before `signSession` is ever called — no fallback/default-tenant path exists. |
| T-02-SC | Tampering | npm installs (openid-client, jose, oauth4webapi) | high | mitigate | Package-legitimacy checkpoint (Task 0, `gate="blocking-human"`) requires human confirmation on npmjs.com before `npm install` runs; never auto-approved. |

</threat_model>
