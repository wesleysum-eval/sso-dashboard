<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> /api/generate | Untrusted input crosses here: only the verified `session` cookie is trusted for tenant resolution; the free-text `prompt` field is untrusted and only ever forwarded to the LLM as prompt context, never used to construct a real API call directly. |
| /api/generate -> AI Gateway | Outbound call carrying `MAKERS_MODELS_KEY`; the LLM's response is untrusted output — treated as pure data, never code, and every field is validated against a closed enum before use. |
| /api/generate -> teo.tencentcloudapi.com | Same outbound trust boundary as Phase 3 — carries the real account's SecretId/SecretKey in the request signature; the response must not be forwarded verbatim to the browser. |

| T-04-03 | Spoofing | edge-functions/api/generate.js (unauthenticated access) | high | mitigate | `verifySession()` is called first, before the LLM call, KV read, or teo call — a missing/invalid session returns 401 immediately (same pattern as Phase 2/3). |
